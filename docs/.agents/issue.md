## I-001：九厂商清单双层手写漂移

**问题描述**：coding-proxy 九家厂商清单在项目卡（`README.md:163`）与深潜块（`README.md:293`）两处全文手写，中英共四份拷贝，无同步机制。PR #7 曾发现卡片侧漏写 Xiaomi（8 家对 9 家），修复方式为只补卡片侧数据——漂移根因（双清单结构）未除。

**表因根因**：v5 重建时同一事实一次性写入两处；两清单命名形不同（Copilot/GitHub Copilot 等），肉眼 diff 困难；lint 只校验 marker 流，散文重复不在守护范围。

**处理方式**（2026-10-18，preening-substrate 结构性熵减）：`README.md:163` 定为唯一权威清单（承诺性陈述，加厂商先改这里）；`:293` 深潜句收敛为「上方卡片点名的九家厂商」回指，保留每家熔断/配额守卫的增量叙述；中英同步镜像。验证：31 用例 + `--lint` 全绿，残留扫描确认厂商名仅存 :163。

**后续防范**：改厂商清单只动 :163；新增手写事实清单时先指定权威位置（编辑契约见 [knowledge-map.md](knowledge-map.md#双语镜像编辑契约卡) 第 7 条）。

**同类影响**：其余手写数字面（`403` 三处、`:249` 的 1,378、`:36` 年度序列 prose）已登记为漂移面，按 C4（角色不同）暂保留，未动。

## I-002：语义级镜像漂移与锚点死链无机器门

**问题描述**：CI lint 与测试只守护 marker 级契约（75/13 流、parity、assets 闭包）；三类承重面无机器守护——① 中英两文件 marker 外文本的语义级镜像漂移；② `<a name>` 锚点 / `#user-content-` 导航链接 / FIG key 三方一致性（破坏即静默死链）；③ `tests/` 31 用例未接 CI（仅本地跑）。

**表因根因**：PR #8 建立 tests 时按最小护栏取舍；锚点前缀是 GitHub 渲染侧行为，仓库内工具不感知。

**处理方式**（2026-10-18，两步闭环）：第一步重构时以 lab 级 gate 脚本护航（锚点三方一致 + marker 行号镜像 + 骨架行号镜像 + 行数相等），编辑契约沉淀至 [knowledge-map.md](knowledge-map.md#双语镜像编辑契约卡)；第二步将检查上收为 [`tests/test_readme_structure.py`](../../tests/test_readme_structure.py)（零依赖纯正则，35 用例之一），并在 `refresh-profile-data.yml` lint job 中接入 `python -m unittest discover tests`，全套护栏由本地自觉变 PR 强制门。

**后续防范**：改任一 README 后跑 knowledge-map 契约卡第 6 条两条命令（与 CI 同款）；新增结构元素（details/锚点/表格）时行级镜像约束由测试自动拦截。

**注意事项**：本地 Markdown 预览不加 `user-content-` 前缀，导航链接在本地必显死链——这是设计使然，以 GitHub 渲染为准。
